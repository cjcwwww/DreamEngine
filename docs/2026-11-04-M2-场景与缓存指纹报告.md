## 2. 参数名必须实测，不能猜

上一轮已经发现中文界面下 `prop.name` 返回中文。本轮把导出范围扩到 CC 系列与两层输入类
（`tools/dump_param_trees.jsx`，输出 `param_trees_b2.tsv`），结论进一步分化：

| 来源 | 参数名形态 | 例子 |
|---|---|---|
| ADBE 内置 | 中文界面返回**中文** | `模糊度`、`最大水平置换`、`颜色` |
| CC 系列（Cycore 第三方风格） | 始终返回**英文** | `Amount`、`Blend w. Original`、`Radius (%)` |

这条区分直接决定配方写法：内置配方必须并列中英双名，CC 配方只用英文即可。
写混了会大面积落空——上一轮 `CC Bender` 渲出来和原图一样，就是这个原因。

本轮新增的 36 条配方覆盖：CC 模糊/颜色/风格化/扭曲/生成/过渡/透视七类，
以及 `ADBE Displacement Map`、`ADBE Compound Blur`、`ADBE Set Matte3`、
`ADBE Fill`、`ADBE Ramp`、`ADBE Gradient Wipe`、`ADBE 4ColorGradient`。

`RECIPE_VERSION` 从 4 升到 5。

## 3. 八类场景全部落地

`recipe.jsx` 的 `sceneFor()` 现在覆盖设计文档 §4.3 的八类枚举，
`layoutFor()` 描述每类场景该怎么搭临时合成：

| 场景 | 判定依据 | 合成结构 |
|---|---|---|
| `no-preview` | 表达式控件 / 音频族 | 不渲图 |
| `text` | 分类「文本」或名字含 text/numbers | 文本素材 |
| `solid-2d` | 名字含 solid/background | 纯色素材 |
| `shape-mask` | 名字含 stroke/trace/outline/wireframe | 形状素材 |
| `footage-2d` | 兜底 | 复合画面素材 |
| `adjustment` | fill / ramp / 4colorgradient / scribble fill | 纯色背板 + 效果层 |
| `two-layer-input` | 置换图 / 复合模糊 / 设置遮罩 / 图层输入类 | 纯色背板 + 图案层 + 效果层 |
| `3d-camera` | 分类「3D 通道」 | 复合画面（生成路径上已排除） |

### 3.1 两层输入：加了第二层还不够，得把图层选择器接上

只搭两层的话，置换图/复合模糊/设置遮罩**画面依然不变**——因为它们的
「图层」选择器默认值是「无」，即使合成里摆了两层也不会自己接上。
新增的 `recipe.bindLayers(effectGroup, 2)` 负责把 `LAYER_INDEX` 类型的属性
统一绑到第 2 层。

图层顺序按 AE 的添加规则设计（后加的在上面）：

```
第 1 层：效果层（作用对象）
第 2 层：图案层（第二输入，高对比黑白竖条 + 白圆）
第 3 层：纯色背板
```

**图案层必须 `enabled = false`。** 它只作为输入参与运算，不该出现在画面上。
第一版没关掉，渲染结果里图案直接压在效果结果上面，看着像效果生效了，其实是图案本身。

**背板必须用纯色而不是同样的复合画面。** 遮罩把上层吃掉一部分后，
露出来的如果是同样的画面，"透明"和"透明+相同背景"看起来一模一样，等于白垫。

|---|---|---|---|
| ADBE Displacement Map | two-layer-input | 被图案驱动的强位移，画面碎成条块 | ✓ 明显 |
| ADBE Compound Blur | two-layer-input | 竖条处强模糊、条间保持清晰 | ✓ 明显 |
| ADBE Set Matte3 | two-layer-input | 画面被遮罩切掉一部分 | ✓ 可见 |
| ADBE Fill | adjustment | 整体被单色覆盖 | ✓ 明显 |
| ADBE Ramp | adjustment | 蓝→橙渐变取代原画面 | ✓ 明显 |
| CC Radial Blur | footage-2d | 中心向外的径向拖影 | ✓ 明显 |

## 4. 缓存指纹：改了配方，旧图自动失效

按设计文档 §4.5，`cacheKey = hash(matchName + 配方版本 + 素材类型@素材版本 + 格子尺寸 + 帧数)`。
AE 版本号刻意不参与，否则每次升级 AE 都要全量重渲。

落地方式：

- `manifest.json` 每条 item 增加 `key` 字段；
- 同时写一份 `data/previews.tsv`（多带 key 一列）——ExtendScript 没有 `JSON.parse`，
  校验必须在 AE 侧做，所以需要一份能被 `split` 的副本；
- `previewgen.staleList()` 重算每条的指纹并与存档比对，返回过期名单；
- 面板在载入清单后调用它：过期卡片**继续显示旧图**（否则用户会以为效果库突然变空），
  但打上橙色角标并自动排进下一次生成队列；
- `queue.reopen()` 把过期条目重开成 pending，与「失败重试」语义分开——
  配方变了不是渲染出错，不该记失败原因。

实测（`tools/run_m3_probe.jsx` 内置的三行样本）：

```
STALE={"checked":3,"stale":["ADBE Glo2"]}
```

指纹一致的那条不报、指纹被改的那条报、没有指纹的旧条目不报——与设计一致。

生产数据上的实测：60 条索引全部带指纹，`staleList` 返回 `{"checked":60,"stale":[]}`。

### 4.1 两份索引，两个语义：`renderFrames` 与 `frames`

打包把静态格子从 6 帧压成 1 帧之后，出现了一个真实的误报：
**60 条里有 40 条被判定为过期**。

原因是两份索引里的 `frames` 含义不同：

| 文件 | 角色 | frames 的含义 |
|---|---|---|
| `manifest.json` | **显示索引**——面板按它取图、决定要不要做 hover 轮播 | 存储帧数（打包后是 1） |
| `previews.tsv` | **缓存索引**——`staleList` 靠它判断要不要重渲 | 渲染帧数（始终是 6） |

指纹是按**渲染参数**算的，所以 `previews.tsv` 必须记渲染帧数；
一旦被打包改成 1，`staleList` 就会拿 1 帧去比对按 6 帧算的指纹，把有效预览全判成过期。

修正后的分工：

- 打包器在写 `previews.tsv` 时保留源目录里的渲染帧数（源目录没有就退回 manifest）；
- 安装脚本原样复制包里的 `previews.tsv`，不自己重新生成；
- 指纹本身不重算——它本来就该描述「这批像素是用什么参数渲出来的」。

实测修正后 `staleList` 回到 `{"checked":60,"stale":[]}`。

### 4.2 一个诚实的边界

早期 29 条预览是在引入指纹之前渲的，它们渲染时的配方/素材版本与现在不同。
这轮重写索引时它们被**按当前版本补盖了指纹**，所以不会被自动判为过期。
也就是说：**这 29 张的实际内容仍可能是旧配方下的结果**（例如 `CC Bender` 那一版）。
彻底解决需要一次性「全部重渲」，目前没有这个入口，属于遗留项。

## 5. 离线批量生成管线

面板上的生成按钮走 CEP 点击，外部鼠标注入进不了 CEF 子窗口（反复实测失败）。
本轮把同一条链路搬到 AE 侧：

```
tools/pick_candidates.mjs     复用 viewmodel 的排除与分类轮转规则 → 输出名单
  ↓ Documents/DreamEngineProbe/next_batch.tsv
tools/run_batch_generate.jsx   读索引 → 分批渲染 → 每批落盘 → 重写索引
  ↓
AfterFX.exe -r <脚本>          免点击执行
```

两个关键设计：

1. **索引每批落盘，不等全部跑完。** 第一版跑完才写，AE 中途崩溃时前面渲好的
   几十张全丢。改成每成功一批就 `writeManifest` 一次后，崩溃只丢当前批。
2. **`AfterFX.exe -r <脚本>` 可以让 AE 启动时直接执行脚本。** 这条让整套验证
   不再依赖菜单点击，是本轮最实用的工具性发现。

## 6. 三个崩溃源（逐个定位）

整批渲染时 AE 进程会直接消失（不是报错，是崩溃），日志断在该批之前。
把批大小从 48 降到 8、再用 `chunk.txt` 降到 1 之后逐个定位：

| 崩溃源 | 现象 | 处置 |
|---|---|---|
| 第三方插件整批混渲（BCC / Sapphire / Universe） | AE 进程消失 | 候选只取内置效果；L1 本来就应由内置构成 |
| `ADBE Apply Color LUT2` | 渲染阶段弹出「选择 LUT 文件」对话框，整批卡死 | 加入排除名单 |
| `CC Drizzle`（上一轮已定位） | 渲染挂起 >5 分钟 | 已排除 |

`ADBE Apply Color LUT2` 与更早发现的 `ADBE Numbers2` / `ADBE Timecode` 是同一类问题：
**带文件选择或模态参数的效果不能在批量路径里渲染**，脚本会一直等输入。

## 7. L1 内置包：帧间去重与打包

静态效果的 6 帧内容完全相同——打包 L1 时就是 6 倍的纯浪费。
`tools/package_l1.mjs` 逐格比较各帧像素，把静态格子压成单帧：

| 情形 | 处理 |
|---|---|
| 整张网都静态 | 只留第 1 帧，6 张变 1 张 |
| 整张网都动态 | 原样保留 |
| 静态与动态混在一起 | 拆成「静态网（单帧）」+「动态网（多帧）」，格位重新排列 |

实测（60 条预览）：

```
静态 59 / 动态 1（只有 CC Glue Gun 随时间变化——它本来就是个画笔）
体积 4.70 MB -> 1.20 MB（25.6%）
打包前后 60/60 条逐格像素完全一致
```

逐格像素比对是硬校验：打包只允许改变存储方式，不允许改变画面。
`tools/test-package.mjs` 用合成图覆盖三种情形，10 项断言。

顺带解决的既有问题：`data/thumbs/*.png` 一直被 gitignore，但 manifest 引用它们——
换机 clone 会全部缺图。现在 `dist/L1/` 作为可分发的内置包入库（1.5 MB），
`tools/install_l1.mjs` 把它装进扩展数据目录，并同步 `previews.tsv`，
保证两份索引描述的是同一批条目（不一致会让过期判定得出错误结论）。

装完之后扩展目录的预览图从 6.2 MB 降到 1.3 MB。

## 9. 遗留

1. **早期 29 张预览的内容仍可能是旧配方结果**（见 §4.1），需要一次性重渲入口。
2. **`data/thumbs/*.png` 仍被 gitignore**，但 manifest 引用它们。换机 clone 会全部缺图。
3. **`3d-camera` 场景实际不可达**：生成路径已经排除了 3D 通道族。
4. **逐条降级路径没被自动验证过**：面板里整批失败会降级为逐条重试，
   这条分支只在真实故障时才会走到。
5. **`ADBE AutoColor` 这类温和效果在缩略图上辨识度低**，需要目视打分才能定是否值得入 L1。
