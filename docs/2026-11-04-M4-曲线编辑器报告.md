## 2. 分层：三个文件，一条边界

设计文档 §2 的硬规矩是「AE 数据读写 100% 留在 .jsx」。M4 在这条边界上遇到了一个
新问题：**面板拖拽要逐帧重绘，数学不能只活在 AE 侧**（每动一下鼠标过一次
`evalScript`，一次往返 10–50ms，体验直接崩）。

两份实现一定会漂移，所以做成「一份数学，两个运行时」：

```
engine/curve_math.js    纯数学（ES3）。CEP 用 <script> 加载，AE 用 $.evalFile 加载
engine/curvelib.jsx     AE 读写（快照 / 写回 / 指纹），依赖 curve_math
js/curve.js             画布、命中测试、拖拽、预设、冲突处理；只发文本协议
```

- `curve_math.js` 后缀是 `.js`（面板要当脚本加载），但它同时跑在 ExtendScript 里，
  因此 `tools/es3check.mjs` 把它单独纳入 ES3 检查（否则它就成了规则黑洞）。
- `curvelib.jsx` 在加载时校验 `AEV_CurveMath` 是否存在，缺了直接抛错
  —— 而不是留下一个「函数全 undefined」的半残模块（M2.5 踩过这个坑）。
- `bridge.js` 的加载清单里 `curve_math.js` 排第一，`curvelib.jsx` 排在 `store` 之后；
  `AEV_Curve` 也进了「关键模块缺失就强制重载」的自愈检查。

## 3. 换算模型

AE 的 temporal ease 由两个数描述：`influence`（把手水平长度占区间时长的百分比，
0.1–100）与 `speed`（把手垂直速度，属性单位/秒）。于是值图上的一段曲线是：

```
P0 = (tA, vA)
P1 = (tA + infOut%·dt,  vA + speedOut·infOut%·dt)
P2 = (tB - infIn%·dt,   vB - speedIn·infIn%·dt)
P3 = (tB, vB)
```

自检：线性关键帧（speed = 弦斜率、influence = 33.33）四点共线，画出来就是直线；
缓动关键帧（speed = 0、influence = 33.33）即 `cubic-bezier(0.333, 0, 0.667, 1)`，
25% 处得 **15.63**、中点速度峰值 **150/s** —— 与 AE 的 Easy Ease 一致。

### 3.1 速度基准按维度分两类（实机修正）

初版假设「speed 就是路径模长速度」，实机证伪了一半：

| 属性类型 | AE 的 speed 语义 | 基准 | 证据 |
|---|---|---|---|
| 一维（滑杆 / 不透明度 / 分离后的单轴） | **带符号的值速度** | 有符号弦斜率 `Δv/Δt` | 100→30 的段上 speed=+100 会让曲线冲到 110；用模长算会往下走，偏差 41px |
| 多维（位置 / 3D 点） | **沿路径的模长速度** | `|ΔP|/Δt` | 用有符号弦算偏差 18–21px，用模长算 1.3–3.5px |

所以 `m = speed ÷ base`，`base` 按 `dims === 1` 分派。写回时用同一基准反算，
保证「读 → 拖 → 写 → 再读」闭环稳定（往返误差 0.000% / 0.003% / 0.184%）。

### 3.2 空间路径按弧长推进

时间决定「走到路径的第几成」，但 AE 是按**弧长**推进，不是按贝塞尔参数。
实测对照（3d-spatial 样本）：参数法最大偏差 70px，弧长法 3.5px。
`curve_math.uAtProgress()` 用 128 段弧长表做映射（128 与 512 的残差相同）。

### 3.3 为什么内部存「斜率倍率 m」而不是 speed

多维属性每个维度有自己的弦斜率，但 temporal ease 本质是**一条统一的时间重映射**。
用 `m = speed ÷ 该维弦斜率` 表示，就能让「同一条缓动作用于所有维度」在数学上自洽：

- 读：`m = speed_ae × speedScale ÷ chord[dominant]`
- 写：`speed = m × chord[d] ÷ speedScale`

主导维取弦斜率最大的那一维（值不变时 m 记 0，把手只能水平拖）。

### 3.4 标定系数是「占位」不是「装饰」

`CALIBRATION = { influenceScale: 1, speedScale: 1 }` 表示完全按文档语义计算。
若实机夹具证明 AE 的实际把手长度与 influence 百分比不成正比，改这两个数而不是改公式。
`tools/check_curve_calibration.mjs` 会做网格搜索并给出建议值，但**不会自动写回源码**。

## 4. 标定：为什么用采样值而不是截图

任务清单原本写的是「像素级对照」。实际实现改成**数值对照**：

`tools/curve_fixture.jsx` 在 AE 里造 9 组受控样本，每组在关键帧区间内取 17 个时间点，
调 `property.valueAtTime()` 采样 —— 这是 AE 内部真实的求值结果，等价于图表编辑器画出来的曲线。
同时 dump 关键帧的原始 ease / 切线 / 插值类型 / 标志位。

`tools/check_curve_calibration.mjs` 用 curvelib 重算同一条曲线，逐点比对，输出：

- 每个样本的最大绝对误差 / 相对量程误差（阈值 2%）
- **多维一致性诊断**：各维 `speed/弦斜率` 的比值是否一致
  → 一致则「统一时间重映射」假设成立；不一致说明要改成逐维 m（当前是近似）
- `influenceScale` / `speedScale` 的建议值（改善 <20% 会明确说「大概率不是系数问题」）

比截图强的三点：能自动化、能定位到「第几段第几维第几个时间点」，也不会把
「公式错了」和「坐标轴映射错了」混为一谈。

### 运行步骤（需要你，约 2 分钟）

```powershell
# 1. 在 AE 里跑夹具（文件 > 脚本 > 运行脚本文件），或：
& "C:\Program Files\Adobe\Adobe After Effects 2021\Support Files\AfterFX.exe" `
  -r "…\tools\curve_fixture.jsx"

# 2. 比对（产物在 我的文档/DreamEngineProbe/M4_curve_fixture.json）
node tools/check_curve_calibration.mjs
```

夹具样本覆盖：一维滑杆、二维位置（未分离）、三维位置 + 显式空间切线、分离维度 X/Y、
自动贝塞尔、roving、定格、influence 极值（0.1 / 100）、负向 speed（过冲）。
用完自动 `remove()` 临时合成，不依赖 Ctrl+Z。

## 4.5 实机结论：七条只有跑起来才知道的事

全部由 `tools/run_m4_live.jsx` 在 AE 2021（18.4.1）上跑出，每条都进过修复与复测。

| # | 发现 | 初版假设 | 实际 | 处理 |
|---|---|---|---|---|
| 1 | 多维属性的 `keyInTemporalEase` | 每维一个 KeyframeEase | **只返回 1 个**；传 2/3 个报「值数组没有 1 元素」 | `buildEase` 只写 1 个，速度按路径模长 |
| 2 | `setSpatialTangentsAtKey` | 数组长度 = 维度 | **必须 3 个**，2D 位置传 2 个也报错 | 按 `max(dims,3)` 补齐 |
| 3 | 插值枚举数值 | LINEAR=6613 / BEZIER=6614 / HOLD=6615 | **LINEAR=6612 / BEZIER=6613 / HOLD=6614** | 加 `typeCode()`，快照与写回都过它 |
| 4 | `speed` 的基准 | 一律按路径模长 | 一维是**带符号值速度**，多维才是路径模长 | 按 `dims === 1` 分派（§3.1） |
| 5 | 空间路径推进方式 | 贝塞尔参数 u | **按弧长** | `uAtProgress()` + 弧长表（§3.2） |
| 6 | 一维属性的 `keyValue()` | 数组 `[v]` | 返回**裸数字** | 快照统一 `valueArr()`；曾导致曲线全平、误差 1e8 |
| 7 | `layers.addSolid()` | 只加图层 | 还会在工程里**新建一个纯色素材项** | 夹具/驱动都记下 `layer.source` 并在收尾删除 |

第 3 条是最贵的一条：枚举记反一位，写进去的贝塞尔被自己的代码判成线性，
于是「拖了没反应」；而第 6 条会让整条曲线静默变平。两者都只有实机能暴露。

## 5. 并发校验：AE 没有属性变化事件

面板读快照时记下每个属性的指纹（时间 / 值 / 插值类型 / 两侧 ease 的 djb2 哈希）。
写回前把 `expect\t<loc>\t<sig>` 一起发过去，`curvelib` 先核对现值：

- 一致 → 在**一个** `beginUndoGroup` 里写完所有操作
- 不一致 → 返回 `conflict`，**一个字节都不写**，面板弹三选一：

| 选项 | 行为 |
|---|---|
| 覆盖 | 重发时带 `force` 并剥掉 `expect` 行（用户显式授权） |
| 重新载入 | 丢掉本地改动，重读 AE 现值 |
| 放弃 | 同「重新载入」，但明确告知「显示的是 AE 当前值」 |

写成功后**重新读一次快照**：AE 可能对 ease 做钳位/规范化，显示值必须以 AE 为准，
不能假设「我写什么 AE 就收什么」。

## 6. 交互约定（都固化成了测试）

| 行为 | 约定 | 理由 |
|---|---|---|
| 点关键帧 | 选中，显示它的入/出把手 | 先选后拖，命中测试不会误抓 |
| 拖把手 | 只改本地模型并重绘，**松手才写 AE** | 否则每个 mousemove 一次 evalScript |
| Shift + 拖 | 只改缓动幅度（influence），斜率不变 | 对应 AE 里的常用手法 |
| Esc | 取消本次拖拽，回滚本地，不写 AE | 拖错了不用去 AE 撤销 |
| 端点 | 首帧无入段、末帧无出段，跳过并提示 | AE 语义如此 |
| roving 键 | 跳过并提示「时间由 AE 排布」 | 写 ease 会与 AE 的时间排布打架 |
| 自动贝塞尔 | 写之前先 `setTemporalAutoBezierAtKey(false)` | 否则 AE 重算把手，写进去的被覆盖 |
| 线性/定格键 | 先把该侧插值类型改成贝塞尔 | 否则 ease 被静默忽略 |
| **值图把手** | **一段曲线由两端各一条把手线决定**：起点引出 P1、终点引出 P2 | 对齐 Flow 的心智模型；拖任一条即改这段的 cubic-bezier |
| **作用范围** | 只作用于**选中的关键帧所在的段**；未选中才作用于整条属性 | 用户明确要求「只对选中的关键帧有效」 |
| **读数** | 画布下方常驻 `cubic-bezier(x1, y1, x2, y2)` | 与 Flow 一致，拖的时候能对着数字校准 |
| **图表切换** | 值 / 速 / 路 收进工具栏右侧的**小方块**，点开是三行 | 面板窄，三个并排按钮会挤掉属性下拉 |
| 预设应用 | 有选中→只作用于选中的键；无选中→作用于全部键 | 后者是最常用的「整段套缓动」，但状态栏会报数量 |

三种图表：

- **值图**：纵轴是属性值，把手 = 两个圆点，横拖改 influence、纵拖改斜率
- **速度图**：纵轴是值/秒，把手的纵坐标直接就是速度
- **路径图**：空间属性专有，横纵轴都是空间坐标（**X/Y 等比**，否则切线方向是假的），
  拖切线只改 `keyOutSpatialTangent` / `keyInSpatialTangent`，与时间曲线完全分轨

## 8. 已知边界

1. **撤销（Ctrl+Z）未做脚本代验。** 写回包在一个 undo 组里（源码契约 + 无头实测覆盖），
   但 `app.executeCommand(Undo)` 在用户工程里可能撤掉用户自己的操作，风险大于收益，
   留作人工按一次。
2. **分离维度（sep-x / sep-y）差 4–7%。** 把位置分离成 X/Y 后，AE 仍保留原 2D 路径
   的空间切线：即使某一轴首末值相同，它也会沿弧线鼓出来（实测 1200 鼓到 1274）。
   面板把分离后的单轴当独立一维曲线，拿不到另一轴的信息，这条差异模型覆盖不到。
   比对工具把它标成 `KNOWN-LIMIT` 而不是 `FAIL`。
3. **非空间多维（缩放）的速度基准未单独标定。** 当前按「多维 → 路径模长」处理；
   缩放没有空间路径，理论上可能更接近「各维一致的值速度」，需要一组缩放样本复核。
3. **速度图的纵轴是瞬时速度，不是 AE 的速度图完整语义。** AE 的速度图还包含
   「把手的斜率在图上的含义随维度变化」等细节，当前只保证曲线数值一致。
4. **自定义缓动库未做**（存自己的曲线为预设）。当前 8 条是内置常量；
   任务清单里的「把调好的曲线存成可复用预设」属于后续增量。
5. **面板还没有「关键帧增删」。** 本版只编辑既有曲线的插值与切线，不动时间与值。
6. **配置文件写入未做**：编辑器状态（上次的属性、图表模式）不持久化。
