# 2026-11-04 · 面板交互修正报告

> 本轮修三个用户反馈的问题，顺带挖出一个隐藏 bug。
> 全部在 AE 2021 实机验证过。

## 1. 左侧分类栏随右侧一起滚

**现象**：拖动右侧预览网格时，左侧的分类列表跟着往上跑，看不到下面的分类了。

**根因**：整个面板是**页面级滚动**——`body` 只有 `min-height: 100%`，没有固定高度，
内容超出视口时整个 document 滚动。`.sidebar` 和 `main` 是 `.workspace` 里的两个 flex 子项，
页面一滚，它们一起移动。

**改法**：改成 app-shell 布局。

```
body      → display:flex; flex-direction:column; height:100vh; overflow:hidden
topbar   → flex:none（原来是 sticky）
controls → flex:none
workspace→ flex:1 1 auto; min-height:0（吃掉剩余高度）
sidebar  → overflow-y:auto（自己滚）
main     → overflow-y:auto（自己滚）
statusbar→ flex:none（原来是 fixed）
```

关键点是 `min-height: 0`：flex 子项默认 `min-height:auto`，内容多高就多高，
不加这一句，`workspace` 会被内容撑破，滚动就又回到页面级。

实测：右侧滚到「波形变形 / 波形环境 / 彩色浮雕」，左侧分类栏纹丝不动。

## 2. 预览框裁切会串格

**现象**：面板比例变化时，效果预览方框裁切出来的画面不对，
有时候会把**别的效果**带进来。

**根因**：缩略框用的是**固定像素**定位。

```js
// 旧代码
thumb.style.backgroundSize = state.manifest.width + "px " + state.manifest.height + "px";
thumb.style.backgroundPosition = "-" + preview.x + "px -" + preview.y + "px";
```

`background-size` 固定成整张网的像素尺寸（1024px），意味着网图以 1:1 像素显示。
但 `.thumb` 的实际渲染宽度是 `width: 100%` + `aspect-ratio: 1`——
**随卡片宽度变化，而卡片宽度由 grid 的 `1fr` 决定**。

格子本身只有 128px。一旦缩略框渲染宽度超过 128px，
`background-position` 指向的那 128px 之外，就会露出相邻格子的画面。

实测：在本机面板宽度下，卡片被拉到 180–280px，**每张都串格**。

**改法**：改用百分比 sprite，让「一格」永远精确等于「一个预览框」。

```js
background-size     = (列数×100)% (行数×100%)     // 整网按格数放大
background-position = 格位百分比                     // 按格位换算
```

百分比定位的公式是 `偏移 = 百分比 × (容器 - 图片)`。
图片放大后比容器大得多，所以归一化时分母是 `(格数 - 1)` 而不是格数。

**验证**：新增 `tools/verify_crop.mjs`，模拟浏览器的百分比定位算法，
算出「缩略框左上角对应源图的哪个像素」，与条目实际格位比对：

```
切片验证：8 个条目 × 5 种缩略框尺寸
  检查 40 次，错位 0 次
  可见区域越界（会露出相邻格子）: 0/40 次
  旧算法（固定像素）在缩略框 > 128px 时会串格：32/40 次
```

实机目视：拖动滑块从 96px 到 280px，每种尺寸下卡片都只显示自己的效果，无串格。

## 3. 预览大小滑块

状态栏右侧新增 range 输入（96–280px），写进 `--thumb-size` CSS 变量，
grid 的列宽跟着变：

```css
grid-template-columns: repeat(auto-fill, minmax(min(var(--thumb-size, 132px), 100%), 1fr));
```

`min(..., 100%)` 是为了在窄面板里不超出可用宽度。

**为什么需要它**：格子是 128px，卡片是 `1fr` 拉伸的。
面板宽的时候卡片被拉到 280px，格子被放大 2.2 倍——细节放大后反而模糊。
滑块让用户自己定一个合适的尺寸。

## 4. 隐藏 bug：sheets 数组顺序与 index 字段不一致

打包器按**落盘顺序**往 `sheets` 数组追加，而每张网有自己的 `index` 字段。
静态流与动态流交错落盘时，数组位置与 `index` 会对不上——实测 5 张网里错位 2 处。

面板原来用 `manifestData.sheets[preview.sheet]` 按数组位置取，
对动画条目会取到错误的网。

```js
// 改为按 index 建索引表
var sheetByIndex = {};
for (var sh = 0; sh < sheetList.length; sh++) {
  sheetByIndex[sheetList[sh].index] = sheetList[sh];
}
var sheet = sheetByIndex[preview.sheet] || {};
```

## 5. 未分类的效果已移除

用户要求「未分类那些效果删掉」。

AE 对一批效果不返回分类字段（实测 **97 个**，主要是 `ADBE CM *` 创意片段集
与 3D 通道族）。它们在 AE 菜单里也没有归属，左侧分类栏放不下。

改在 `viewmodel.isExcludable`——面板与离线清单生成共用这一份判断：

```js
if (!category.trim()) return true;
```

**L1 目标清单：307 → 211 条。**

新增 `tools/prune_manifest.mjs`：按目标清单裁剪索引，
不必为了去掉几条而重渲一遍（重渲 307 条要几分钟，裁剪是秒级）。

裁剪后打包仍然正确：`package_l1.mjs` 会做全局重排，
留下的条目重新填满整网，5 张网 / 4.33 MB。

## 后续调整：滑块范围改为 48–180px

用户实测后要求把预览大小滑块从 96–280px 改为 **48–180px**：下限更小、
上限更收敛，常用区间内调节更细。同步改动：

- `index.html`：`min=48 max=180 step=2 value=132`。原 `step=8` 会让 132
  被浏览器吸附到 136，换成 step=2 后默认值落在合法刻度上。
- `library.js`：`THUMB_MIN/THUMB_MAX = 48/180`，滑块刻度**固定不变**，
  不再按窗口比例改写 `max`；实际格子仍按可用宽度收敛、对齐到 step=2 后
  写回滑块，保证「标多少、格子就是多少」。
- `style.css`：小于 80px 时给网格加 `compact` 类，收紧卡片文字区与间距，
  让 48px 档仍然可读。
- 验证档位同步到新范围：`measure_layout.mjs` 6 档 × 8 种面板宽度、
  `verify_crop.mjs` 6 种缩略框尺寸；`test-engine.mjs` 换成范围恒定的断言。
