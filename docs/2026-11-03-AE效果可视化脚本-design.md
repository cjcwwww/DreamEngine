日期：2026-11-03
状态：已批准（方案 A + 全部细节槽位确认完毕）
修订：v2 —— 预设改为**用户自主导入（可批量）**，取消程序自动扫描预设目录（见 §6）

## 0. 背景与用户目标

自研 After Effects 脚本，用于把"效果本身"和"自己的预设"变成可视化资产，并附带一个类 Flow 的关键帧曲线快捷编辑器。

三个模块：

1. **AE 自带效果 + 已安装插件效果的可视化** —— 预览墙（自动创建临时合成、套效果、渲染小图）
2. **自己导入预设的可视化** —— 预设墙 / 预设库，同样是自动渲染预览
3. **类 Flow 曲线快捷编辑** —— 编辑对象为**关键帧时间/空间插值曲线**（temporal ease 的 speed + influence、spatial tangent），非效果内置曲线参数、非值曲线

### 已确认的关键决策（按对话顺序）

| 决策点 | 结论 |
|---|---|
| "可视化"的形态 | 自动渲染缩略图预览墙（非参数清单、非并排对比、非文档化） |
| 技术栈 | 方案 A：**CEP 薄 UI + ExtendScript 厚核心 + aerender 离线生成**，预留 UXP 迁移门 |
| 兼容版本 | 必须覆盖 CC2022 / CC2023 及更早 → 直接排除现在押 UXP |
| 预览来源策略 | **内置为主、现场渲染兜底**：脚本内置绝大多数常用效果的预览，只解析未内置的少数 |
| 卡片内容 | 只有 **效果名（加粗）· 效果类/插件名** + 预览图；**不做效果说明文案** |
| 中英文切换 | **名字全部内置**（不依赖运行时采集），内置可切换中文/英文 |
| 第三方插件名 | 也内置，**从网上检索整理**（含中文对照名），需双源核对 |
| 脚本类插件 | **不管**（Duik 等生成的 `Pseudo/` 伪效果一律排除，不做收录） |
| 收录范围 | 只收录常见常用插件包，T0 清单已确认 |
| 分发 | 默认只自己用，不做 ZXP 打包 |

## 1. 技术选型依据（事实与来源）

### 1.1 Adobe 官方扩展性迁移时间线

来源：Adobe Developer 官方博客《CEP to UXP: Creative Cloud Plugin Migration Timeline》，2026-09-24。

- After Effects 的 **UXP 插件公测**：2026 年 11 月起
- After Effects **停止接受新 CEP 提交 + CEP 默认关闭**：2028 年 12 月
- CEP 从旗舰应用中移除：**2029 年底**（自 2029 年 12 月起不再包含在应用中）
- 每个旗舰应用从 UXP 公测起，**保证至少 2 年**才在新版本中移除 CEP
- 原文明确：**ExtendScripts 不受本次迁移影响**

结论：核心业务逻辑压在 ExtendScript 上是长期安全的；CEP 只是"到 2029 年可整体替换的一次性 UI 壳"。同时 UXP 不覆盖 CC2022/2023，与兼容要求冲突，故现阶段不作主线。

### 1.2 已核实的 AE 脚本 API 能力

来源：After Effects Scripting Guide（docsforadobe 镜像，ae-scripting.docsforadobe.dev）。

- `app.effects`：数组，每项含 `displayName` / `category` / `matchName` / `version`，即**全部可用效果（含第三方插件效果）可枚举**。`displayName`/`category` 为**当前 AE 界面语言的本地化名**；`matchName` 跨语言、跨版本不变。
- 套效果：`layer.property("ADBE Effect Parade").addProperty(matchName)`（文档中 Dropdown 示例亦使用 `addProperty`）。
- 参数元数据：`Property.propertyValueType`、`hasMin/minValue/maxValue`、`unitsText`、`canVaryOverTime`、`isSpatial`、`expression`/`expressionEnabled`、`numKeys`、`selectedKeys`。
- 关键帧插值（模块 3 全部依赖项，均为文档化 API）：
  `keyInInterpolationType` / `keyOutInterpolationType` / `setInterpolationTypeAtKey`；
  `keyInTemporalEase` / `keyOutTemporalEase` / `setTemporalEaseAtKey`（`KeyframeEase` = speed + influence）；
  `keyInSpatialTangent` / `keyOutSpatialTangent` / `setSpatialTangentsAtKey`；
  `keySpatialAutoBezier` / `keySpatialContinuous` / `keyTemporalAutoBezier` / `keyTemporalContinuous` / `keyRoving` 及各自 setter。
- 单帧/区间渲染：`app.project.renderQueue.items.add(comp)` → `RenderQueueItem.timeSpanStart`、`timeSpanDuration`（均 read/write）、`skipFrames`、`applyTemplate()`、`status`、`onStatusChanged` 回调；`OutputModule.applyTemplate()` + `setSettings()` 设输出路径。
  注：`Format` 本身**不是可写设置项**，必须通过切换 output module 模板来改格式（来源：Adobe 社区官方答复）。
- **`Layer.applyPreset(File)`**：文档化 API，可从脚本应用 `.ffx` 动画预设。
  ⚠️ 文档原文警告：预设作用于**该图层所属合成中当前被选中的图层**；若无任何图层被选中，会应用到**新建的纯色层**。
- `Layer.copyToComp()`：文档记载 13.7+ 存在"被复制图层带效果时，用户撤销会导致 AE 崩溃"的警告 → 项目清理不得依赖 undo。
- **下拉选项文字的版本门槛**：`Property.propertyParameters` / `Property.valueText` 标注为 **After Effects 26.0 新增** → CC2022/2023 上下拉框只能拿到索引数字。
- 脚本文件写入前提：需在 首选项 > 脚本和表达式 中勾选"允许脚本写入文件和访问网络"（来源：Adobe helpx「After Effects 中的脚本」）。
- `.ffx` 格式：绝大部分为 **RIFX**（RIFF 扩展）二进制，Adobe 社区明确"不可直接编辑" → **不自行解析 .ffx**。
- 预设目录：程序内置预设位于 AE `Presets` 目录；用户创建/导入的预设位于 `Documents/Adobe/After Effects/<版本>/User Presets`（来源：Adobe helpx）。

### 1.3 第三方插件名字的数据源（已验证可得）

- `matchName ↔ 英文名` 合集：David Torno《After Effects Plugin Match Names》（provideocoalition）、fendrafx Plugin Match Names List、GitHub 社区 matchnames 仓库、docsforadobe 第一方效果 matchName 表。
- `英文名 → 中文名` 对照：蓝宝石 Sapphire 有完整中英对照（例：S_Glow 发光、S_LensFlare 镜头光晕、S_WarpBubble 噪波变形、S_HalfTone 双色点阵、S_Kaleido 万花筒）；BCC 有中英对照表；Red Giant 系产品中文名在厂商中文页与社区资料中普遍存在（Colorista 调色师、Cosmo 润肤磨皮、Optical Glow 智能辉光、Shine 放射光、Starglow 星光、Sound Keys 音频关键帧）。
- 规模参照：Sapphire 单包即 270+ 效果（来源：检索到的产品资料，需按质检规则二次核对）。**因此收录范围必须按"插件包"划定，不能按效果无限扩。**

## 2. 总体架构

```
UI 层 · CEP/HTML（薄层：只负责绘制与收事件，可整体替换）
   ├ 预览墙        sprite sheet + background-position 切片；名字加粗 + 分类小字
   ├ 预设库        分组树 + 帧序列轮播放动 + 依赖提示
   ├ 曲线编辑器     SVG/Canvas 拖拽 + 写回
   ├ 生成控制台     队列 / 进度 / 失败清单 / 预览不准标记
   └ 设置          语言(中/英，第三方自动降级英文)、标准素材、缓存目录、批渲参数
        │  只传 JSON 字符串，不共享对象引用
        ▼
核心层 · ExtendScript（厚层：长期资产，可脱离面板在 File>Scripts 独立运行）
   ├ catalog     枚举 app.effects + 参数树 → catalog.json
   ├ names       内置双语名表读取/匹配/兜底
   ├ recipe      演示配方加载、匹配、启发式兜底
   ├ previewgen  预览合成搭建 + 渲染队列配置（单帧 / N 帧）
   ├ presetlib   预设目录扫描 + applyPreset 安全包装
   ├ curvelib    temporal ease / spatial tangent ↔ 贝塞尔 换算
   └ store       JSON 读写、缓存指纹、失效与清理
        ▲
离线生成器 · 开发期用 aerender 子进程复用同一套 previewgen + recipe + names
```

设计原则：**AE 数据读写 100% 留在 .jsx**，CEP 侧不出现任何 AE 对象。这是对冲 2028/2029 CEP 退场的唯一保险，同时让"纯 jsx 版"随时可退化为兜底交付形态。

## 4. 模块 1：效果预览墙

### 4.1 预览来源三层

| 层 | 来源 | 产生时机 | 覆盖 |
|---|---|---|---|
| **L1 内置包** | 开发期离线预生成，打进 `data/thumbs/` | 开发者跑一次生成器 | 绝大多数常用效果，装机即有、零渲染 |
| **L2 本地缓存** | 用户机现场渲染，写用户目录 | 首次需要时按需/批量 | L1 未覆盖（生僻内置效果、插件效果） |
| **L3 占位** | 不生成 | 不适用 / 失败 | 表达式控件族、音频族、缺素材、渲染失败 |

运行时主流程：

```
枚举 app.effects
  → 读 L1 manifest + L2 index
  → 差集：
      detected ∩ bundled          → 直接显示内置图（零渲染）
      detected − bundled − cached → 进待生成队列（面板显示数量，按需或批量）
      bundled − detected          → 灰显"当前机器未安装"
```

匹配主键**只用 `matchName`**。`app.effects[i].version` 与 AE 主版本只作记录（角标"预览来自 AE 2024"），**不参与失效判断**，否则每次升级触发全量重渲。

### 4.2 Contact Sheet 批量渲染（核心成本优化）

- 一张 `2048×2048` 整网 = `8×8` 格，每格 `256px`（尺寸可配；实际纹理上限需 M0 实测）
- 每格是一个**独立预合成**，内含标准素材 + 只挂一个效果 → 混合模式 / 3D 变换 / track matte 互不污染
- 同批所有预合成 in/out 时间对齐 → 共享时间轴
- 用 `timeSpanStart` + `timeSpanDuration` + PNG 序列模板，一次渲一批

渲染次数公式：`⌈效果数 / 每网格数⌉ × 帧数`
示例（输入值：100 效果、每网 64 格、12 帧）：朴素 `100 × 12 = 1200` 次；网格法 `⌈100/64⌉ = 2` 张/帧 × `12` = `24` 次。

面板端切片**不需要任何图像工具**：整网图作前景图，`background-size: 2048px` + `background-position: -(col×256) -(row×256)`；动画即按帧号切换 `src` 轮播。动图编码优先 GIF/WebP 或帧序列轮播，**不假设 CEF 支持 H.264**。

### 4.3 演示配方（demo recipe）—— 模块 1 的真实工作量

"内置"不等于白送：套默认参数时一半效果渲出来看不出名堂。每个内置效果需要一条配方。

配方字段：`matchName` / 场景类型 / 素材选择 / 参数覆盖(演示值) / 展示时点 t / 帧数 / 是否动画 / 失败标记

**场景类型枚举**（决定临时合成怎么搭，是覆盖率的硬约束）：

- `solid-2d` 纯色 2D 效果（占比最大）
- `footage-2d` 需真实画面（模糊、校正、键控、噪波）
- `text` 文字类效果与变形器
- `shape-mask` 依赖蒙版/形状路径（弯曲、描边、Trace Path 类）
- `adjustment` 调整层（需下层背景）
- `two-layer-input` 需前景+背景双素材（matte / 图层输入类）
- `3d-camera` 需 3D 图层 + 摄像机/灯光
- `no-preview` **表达式控件族**（Slider / Angle / Color / Checkbox / Dropdown / Point Control 等）、**音频族**（Denoise、Parametric EQ、Bass&Treble）→ 不渲图，退化为纯文字列表项，可默认折叠

**L2 启发式兜底**（无配方也能出大致可用的图）：按 `propertyValueType` 自动填演示值 —— OneD 取 `minValue/maxValue` 中值（无 min/max 时按类型给经验值）；COLOR 给高饱和色；TwoD_SPATIAL 给中心+偏移；Popup 取第 2 项；Checkbox 取 true；Layer/Mask index 取 1；展示时点取合成 50%。

**落地节奏（成本控制关键）**：先用启发式跑通全量 → 面板里"预览不准"标记（本地标记，不涉文案）→ 回开发期补配方 → 重新打包 L1。配方是**可持续增量积累的资产，不要求第一版做完**。

### 4.4 标准素材

四套固定素材，一次配置长期复用：纯色 / 真实视频片段 / 文本 / 形状或蒙版。素材变更 → `assetFingerprint` 变 → 相关条目失效。

### 4.5 缓存指纹

```
key = hash( matchName + recipeVersion + assetFingerprint + tileSize + frameCount )
```
配合渲染队列 `Skip Existing Files` + L2 index，支持中断后续渲。

## 5. 名字表设计（双语切换）

### 5.1 三层来源

```
L-A  AE 内置效果       官方中英双语（matchName 清单 + Adobe 中英文效果列表整理）
L-B  主流第三方插件包   联网检索整理，按包分组维护
L-C  运行时兜底         表外效果用 app.effects 的 displayName，中英显示同一个
```

主键恒为 `matchName`，**绝不用 displayName 做匹配**。

### 5.2 关键洞察：汉化版插件会污染 displayName 的语言

国内大量插件为汉化包，效果名被直接改成中文 → **同一 matchName 在不同机器上 displayName 语言不可控**（装了汉化=中文，未装=英文）。

因此面板切换语言时**只读内置字段、不信任 displayName 的语言状态**，displayName 降级为"仅用于校验 matchName 是否对不上"。副作用是内置表反而能替汉化插件给出正确英文名。

### 5.3 记录字段

```
matchName, nameZh, nameEn, categoryZh, categoryEn,
pluginHint, nameZhSource: official|community|none,
categorySource, verifiedAt, pluginVersion, covered: bool
```

### 5.4 数据质检规则（防错名进产品）

1. 中文名来源优先级：**厂商官方中文页 > 中英对照表（≥2 个独立来源一致）> 单源社区译名**。
2. 两源译名冲突 → 不合并、不择一当定论，保留分歧字段，面板 hover 显示备选。
3. 仅来自资源站/自媒体的译名 → 标 `community`，卡片小字带来源色点。
4. `nameZhSource: none` → 中文位直接显示英文名，**绝不机翻、不拼音化**。
5. 合规边界：只把名字整理成自有数据文件，**不打包任何汉化补丁、不复制受版权保护的对照表原图/整表**；来源站点记录在维护文档备查。
6. **第三方插件的中文名不存在 `official` 级**（Boris FX 中文站明确官方未提供中文版 Sapphire/BCC，中文显示名全部来自第三方汉化补丁）。插件侧可达上限只有"社区双源一致"，因此：
   - 主源制度：以按具体汉化版本整理的对照表为主源，其余源只用于发现分歧、不用于覆盖译名
   - 视觉分层：第一方中文名（官方级）与第三方中文名（社区级）不得同权重，后者必须带来源标识
7. **不强求中文名（最终策略，取代上一轮拟定的"三态语言设置"）**。
   既然第三方插件的中文显示名全部来自汉化补丁、不是官方内容，那么借用社区译名就没有正当性——专有名词与品牌名本就不该被翻译。规则定为：

   - **语言设置回退为两态**：`中文` / `English`，不再需要"跟随本机"第三态
   - 中文模式下：**第一方效果**显示官方中文名（helpx 级，266 条已就绪）；**第三方插件效果默认仍显示英文原名**
   - 插件表里的社区译名一律降级为候选：**只备查、不参与显示**
   - 插件效果获得中文名的唯一途径：T0.1 实测的 `displayName` 本身是中文（说明你确实装了汉化包）→ 由 `join_matchnames.py` 的 `zh_status` 字段自动判 `zh_verified` / `zh_replaced` / `en_only`，**用的是你机器上的真实名字，不是我抄来的译名**
   - 推论：**大量效果只含英文名是正常终态，不是数据缺失**。覆盖率报告里"仅英文（合法状态）"是正向指标

8. 由此取消的取数工作：Sapphire / Red Giant 系 / Video Copilot / X-Particles / Re:Map / Toolchefs 的中文对照检索与双源交叉**全部不再必要**。剩余包只缺英文效果名目录，而这些运行时 `app.effects` 天然就有 → **B3–B5 从"必须完成的数据活"降级为"可选整理"**。

### 5.5 收录范围（已确认）

- T0 插件包：BorisFX Sapphire、Boris BCC、Red Giant Trapcode Suite、Magic Bullet Suite、VFX Suite、Universe、Video Copilot（Saber 等免费包 + Element 3D）、X-Particles、Re:Map、Toolchefs
- 内置效果：AE 官方全量中英表（第一方，覆盖完整）
- **明确排除**：脚本类插件产生的 `Pseudo/` 伪效果（Duik 等）——数量由用户创建决定，无公开清单，一律走 L-C 兜底
- 冷门/小众插件：落到 L-C，面板标"未收录，显示本机名"

### 5.6 卡片最终形态

```
┌────────────────┐
│   预览 256px    │  动画效果按帧轮播；静态图不轮播
├────────────────┤
│ 高斯模糊         │  加粗(font-weight 600) = nameZh/nameEn
│ 模糊 · 内置      │  12px 灰字 = 分类/插件归属 + 确认|推断|未收录 色点
└────────────────┘
```
缺图时图片区退化为灰占位块 + 居中"未生成/不适用"，名字与分类照常显示。

### 5.7b 插件表改两段式键（M0.5 实施中确定的修订）

第三方插件的 matchName **没有公开权威清单**——网上可得的对照资料都是按「英文显示名 ↔ 中文显示名」组织的。因此插件名字表不再硬套 matchName 主键，改为两段：

1. 先建 `name_en → name_zh / cat_zh / 插件包 / 来源 / 置信度`
2. T0.1 实测出本机 `(matchName, displayName)` 后做 **双向对撞**：正向比 `name_en`，反向比 `name_zh`（因为汉化版插件的 displayName 本身就是中文），命中才落 matchName，未命中进 unmatched 清单

比较前做归一化（去首尾空格、压缩连续空格、大小写不敏感）。最终交付仍是 matchName 主键的统一表，插件侧只是构建流程多一步 join。

### 5.7 分类 ≠ 插件名（诚实约束）

`app.effects[i].category` 是效果菜单分类标签，**不等于"来自哪个插件"**：厂商行为不统一（有的用插件名作分类，有的塞进通用分类，有的每个效果自造分类），且**没有任何 documented API 能取到效果对应的 .aex 文件名**。

落地方案（三级优先级）：
1. `plugins-map.json` 人工指定（一次纠偏，几十个插件包规模可控）
2. matchName 前缀规律推断（第三方常带厂商缩写前缀，如 `S_`、`APC`）
3. 原始 `category`

显示：`手动映射 > 推断 > 原始分类`，并用不同色点区分"确认 / 推断"。

## 6. 模块 2：预设可视化

### 6.1 导入方式（用户主动，程序不自动扫描）

程序**不递归扫描任何预设目录、不自动入库**。库的初始状态为空，一切由用户导入产生。

四个入口，覆盖"少量精选"到"整包批量"：

| 入口 | 操作 | 批量能力 |
|---|---|---|
| 选文件导入 | `File.openDialog(prompt, filter, multiSelection=true)` 多选 `.ffx` | 一次任意个 |
| 选文件夹导入 | `Folder.selectDialog` 选一个目录，递归取其中 `.ffx` | 整包导入，**保留相对路径作为分组** |
| 拖拽导入 | 从系统资源管理器把文件/文件夹拖进面板 | 一次任意个 |
| 快捷跳转 | 提供"打开 Presets / User Presets 目录"按钮，只负责定位到目录供上面入口选取 | 不自动扫描 |

拖拽能否拿到真实文件路径取决于 CEP/CEF 的实现（HTML5 `dataTransfer.files[i].path` 是扩展属性），**列为 M0 待实测项**；不可用时降级为"选文件/选文件夹"两个入口，功能不缺失。

### 6.2 入库策略：复制入自有库（默认）

`.ffx` 体积极小（据 FILExt 统计，RIFX 格式的 .ffx 平均约 36 KB，常见范围 4 KB ~ 130 KB），因此默认**把文件复制进 `library/`** 而不是只登记外部路径：

- 用户之后清理下载目录、重装系统、换机器，库不会失效
- 库自包含，迁移机器只需复制 `<产品名>` 目录 + 重新生成预览
- 代价是磁盘占用可忽略

同时保留 `sourcePath` 与 `contentHash`：
- `contentHash` 作为去重键，重复导入直接跳过并提示"已存在于 <分组>"
- `sourcePath` 仅用于"显示原文件位置"，不作为依赖

（可选：设置里留一个"仅引用原路径"模式给不想复制的人，默认不启用。）

### 6.3 组织与检索

因为不再依赖目录结构，分组改为三条并存：

1. **导入批次分组**：默认按批次建组（`2026-11-03 · 42 个`），可整批撤销
2. **文件夹相对路径分组**：走"选文件夹导入"时自动保留原始层级（这是唯一能从磁盘带过来的结构信息）
3. **手动分组 / 标签**：多选后建组、打标签；一条预设可属多标签

检索按名字匹配（预设名即去扩展名的文件名，多为英文，**不做机器翻译**），支持按"适用图层类型""依赖某效果""是否有预览""导入批次"筛选。

### 6.4 预览生成与安全包装

流程：临时合成 → 建 pristine 测试层 → **精确隔离选中态** → `Layer.applyPreset(presetFile)` → 读回图层状态 → 渲 N 帧。

`applyPreset` 的文档级陷阱必须正面处理：
1. 调用前清空整个合成选区，只选中目标层（因为它作用于"当前选中图层"而非调用者）
2. 调用后做**结果校验**：效果数/属性变化为空 → 判为"素材类型不适用"
3. 按失败自动换场景类型重试：`solid → text → footage → adjustment`，首个成功即写入 `preset-library.json` 的"适用图层类型"，下次不再试错
4. 无选中会新建纯色层 → 用后即删，且**清理走 `remove()` 不依赖 Ctrl+Z**（规避 `copyToComp` 文档记载的 undo 崩溃）

**批量导入走与 L2 预览生成同一套任务队列**：导入动作本身只做"复制入库 + 建索引（状态 pending）"，渲染排入队列，可中断、可续做、可分批，失败条目带原因（`failed:reason`）并可单独重试。

这带来一个重要的成本变化：预览渲染量从"扫描到的预设总数（可能上千）"变成"用户实际导入的数量"，**模块 2 的渲染成本由用户自己决定，风险直接归零**。

### 6.5 附带能力（吃模块 1 的红利）

应用后读到的效果 matchName 列表 = 该预设的**依赖清单**，可显示"依赖 3 个插件效果，已安装 2 个"，并支持反查"哪些预设用了某个效果"。

### 7.1 数据读写

### 7.2 换算与标定（本项目最大调试不确定点）

把"speed + influence"映射成屏幕贝塞尔把手：influence → 把手水平长度比例，speed → 斜率；需处理值图表与速度图表两套映射、维度分离（separation leader/follower）、空间属性与时间属性分轨。

⚠️ **必须做像素级对照标定**：同一组关键帧，在 AE 原生图表编辑器与面板中逐一比对，靠推导极易对不上。M4 的第一步是"对照标定夹具"，不是画 UI。

### 7.3 结构性限制与对策

AE 脚本**没有属性变化事件**，面板无法订阅"用户在时间轴改了关键帧"。

- 显式"重新读取"按钮 + 每次操作前重取当前选中属性
- **乐观并发校验**：写回前比对面板快照与 AE 现值，不一致弹"外部已修改 → 覆盖 / 放弃 / 重新载入"，绝不静默覆盖
- 面板数据视为"事务草稿"，编辑期间不做外部同步

## 11. 风险清单（按杀伤力排序）

1. **曲线换算与 AE 原生图表编辑器对不齐** → 面板与 AE 实际不一致，是体验致命伤。对策：M4 先做对照标定夹具。
2. **配方工作量超预估** → 分层覆盖 + 启发式兜底 + 面板反馈闭环，把补配方变成渐进任务。
3. **`applyPreset` 选层语义 + undo 崩溃警告** → 选区隔离、结果校验、多场景重试、清理不依赖 undo。
4. **渲染阻塞正在使用的 AE** → 大批量走 aerender 子进程；面板内生成走分批小队列。
5. **内置包体积**（sprite 网络 + 多帧极易膨胀）→ L1 只给"静态首帧全覆盖 + 动画仅 T0 精选"，帧数上限由 M0 实测体积定。
6. **名字表错译风险** → 双源核对 + 来源标注 + 分歧保留 + 面板色点区分置信度。
7. **CEP 2028.12 默认关闭 / 2029 底移除** → 核心全在 jsx，UI 层做薄可替换；ExtendScript 官方明确不受影响。
8. **老版本下拉选项名不可读** → 内置映射表补内置效果，插件效果明确标注"当前版本无法读取选项名"。
9. **合规** → 预览图由自有机器渲染（无问题）；不内置第三方插件的宣传图/文档原文；汉化补丁与对照表原表不打包。
